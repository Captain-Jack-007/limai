# Research Report Generator Skill

## Purpose
Generate and update professional research reports following strict guidelines. This skill ensures consistent quality, incremental evolution, and proper sourcing.

---

## ★★★ 核心优先级声明 ★★★

### 增量进化准则：最高优先级（NO.1原则）

**任何时候，生成/更新研报都必须遵循增量进化准则，违者视为不合格。**

| 优先级 | 规则名称 | 说明 |
|-------|---------|------|
| **★NO.1 最高** | **增量进化准则** | 必须读取旧研报、保留历史数据、禁止删除重写 |
| ★NO.2 | 数据可信度分级 | 每个数据必须标注来源和可信度等级 |
| ★NO.3 | 推导过程要求 | 每个主要结论必须附推导过程+局限性声明 |
| ★NO.4 | WSJ风格 | 首句即数据、主动语态、量化表达 |
| ★NO.5 | 十大章节框架 | 任何研报必须遵循十大章节框架，违者视为不合格 |

**违禁行为（一旦出现，研报不合格）：**
- ❌ 未读取旧研报就生成新版
- ❌ 删除/覆盖旧研报内容（哪怕重新排版也不允许）
- ❌ 重新生成旧章节的文字内容（V1原文一字不改）
- ❌ **生成原文内容**：增量更新时，将旧章节内容重新生成一遍（哪怕文字相近）
- ❌ 创建重复文件（旧版不删除）
- ❌ 新版本不包含历史数据
- ❌ 不添加更新日志
- ❌ 使用含版本后缀的文件名（如 `_V1.docx`、`_完整版.docx`、`_更新版.docx`）
- ❌ 未覆盖保存到 `/root/项目研报/{项目名}研报.docx` 路径
- ❌ 同一项目存在多个研报文件
- ❌ **将旧版本正文内容重新写入新文件**（正确做法：直接复制旧文件元素）
- ❌ **未使用十大章节框架**：任何研报（无论行业）必须严格遵循下述十大章节模板，缺章或章节顺序错误均视为不合格
- ❌ **捏造数据**：任何数据（数字/百分比/数量）必须是已知来源中的真实数据，绝对禁止凭空捏造
- ❌ **捏造来源标注**：绝对禁止为不存在的数据"编造"来源和可信度等级（★★★★★等），一经发现视为严重违规
- ❌ **过度推断**：超出已知数据范围的推测性结论必须标注"本报告分析估算，非实际数据"，禁止将推测当事实写入正文

**增量进化的正确做法（重要）：**

| 增量场景 | 正确做法 | 错误做法 |
|---------|---------|---------|
| V1有8章，V2新增第9-10章 | V1八章内容一字不改，直接追加新章节 | 重新生成V1八章文字 |
| 原章节末尾需要补充新小节 | 在原小节之后插入新节 | 重新生成原小节 |
| 新增情报需要深化原内容 | 在原内容之后追加新段落 | 重新生成原段落文字 |
| 保留原文件还是覆盖 | 覆盖保存（文件路径唯一） | 创建_V2等版本文件 |

**"保留"的确切含义：**
- 旧版本的所有文字内容必须**原样复制**进新文档（不是重新生成，是复制）
- 旧版本的表格数据必须原样复制
- 旧版本的章节编号和层级结构必须保留
- 唯一允许的变动：在末尾添加新章节，或在原章节之后插入新的小节

**正确保留旧内容的技术方法（重要）：**

❌ 错误做法（被禁止）：
```python
# 绝对禁止：把旧内容重新"写"一遍
for p in v1_paragraphs:
    new_doc.add_paragraph(p.text)  # 这属于"重新生成"，违禁！
```

✅ 正确做法：
```python
# 正确：用XML元素复制的方式原样保留
from docx.oxml import OxmlElement
for element in v1_doc.element.body:
    new_doc.element.body.append(element.__copy__())  # 直接复制XML节点，不是重新生成文字
```
**核心区别**：复制XML元素 = 原样保留；重新写入text = 生成原文内容（违禁）

**正确增量更新示例：**
```
V1内容（306段落）：第1-8章全部保留
  → 技术实现：直接复制V1.docx的XML元素到新文档（非重新写入文字）

V2增量内容（新增）：
  - 第9章：商业落地路径（全新文字）
  - 第10章：发展前景与战略建议（全新文字）
  - 1.4节（在第1章末尾新增，1.1/1.2/1.3保持原样）
  - 5.5节（在第5章末尾新增，前面5.1-5.4保持原样）
```

**操作清单（每次增量更新必须执行）：**
1. 读取旧研报 `Document('/root/项目研报/{项目名}研报.docx')`
2. 用 `element.__copy__()` 将旧版本所有元素复制进新文档
3. 在新文档末尾（或章节末尾）追加新内容
4. 覆盖保存到原路径（同一文件）
5. 更新末尾的更新日志

**文件命名规则（重申）：**
- 每项目只允许一个文件路径：`/root/项目研报/{项目名}研报.docx`
- 更新时直接覆盖保存，不创建 `_V2`、`_备份`、`_更新版` 等额外文件

### 增量进化四步曲

```
┌─────────────────────────────────────────────────────────────┐
│  增量进化准则执行流程                                          │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  步骤1：读取旧研报 ──→ 必须读取，文件路径：/root/项目研报/{项目名}研报.docx  │
│         ↓                                                    │
│  步骤2：保留历史数据 ──→ 所有历史数据必须保留到新版本中          │
│         ↓                                                    │
│  步骤3：增量深化 ──→ 在原基础上新增/深化，不删除                │
│         ↓                                                    │
│  步骤4：记录日志 ──→ 文档末尾记录更新历史                       │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

**正确做法 vs 错误做法：**

| 做法 | 正确 | 错误 |
|-----|------|------|
| 生成新版 | 读取旧版 → 增量深化 → 保存覆盖 | 直接删除旧版 → 生成全新 |
| 更新数据 | 保留旧数据 → 更新变化部分 | 删除旧数据 → 全部重写 |
| 保存文件 | 覆盖保存 `/root/项目研报/{项目}.docx` | 创建新文件 `{项目}V2.docx` |
| 版本命名 | 保持同一文件名，末尾加更新日志 | 创建多个版本文件 |

#### 第二步：时效性校验（Temporal Validation）

**核心准则：**
- 所有宏观数据和财务指标 **必须** 使用2025年年报或2026年Q1季报后的数据
- 禁止使用超过12个月的历史数据作为核心论据

**时间判定规则：**

| 数据类型 | 最低时效要求 | 超期处理 |
|---------|------------|---------|
| 财务数据（营收、利润） | 2025年Q4或2026年Q1 | 搜索"latest"更新 |
| 市场数据（份额、规模） | 2024年Q4或2025年Q1 | 搜索最新预测 |
| 政策数据 | 无时效限制 | 标注发布日期 |
| 技术参数 | 2024年内 | 标注数据年份 |

**强制更新触发条件：**
```
如果检索到的核心数据早于12个月前（晚于 [当前月份-12]），
必须追加搜索：
"[Project] latest data March 2026"
"[Project] 2026 first quarter update"
```

**数据日期标注格式：**
```
正文引用示例：
"2025年营收120亿元（as of Dec. 2025）[1]"
"市场份额35%（as of Q1 2026）[2]"
```

---

#### 第三步：信源过滤（Source Filtering）

**自动丢弃的非权威来源：**

| 丢弃类型 | 示例 | 原因 |
|---------|------|------|
| 自媒体 | 微信公众号个人号、微博个人博主 | 无公信力 |
| 综合性门户网站 | 网易、新浪新闻页 | 无专业背书 |
| 论坛帖子 | 雪球散户帖、贴吧讨论 | 数据未经核实 |
| 付费软文 | 不知名网站付费推广 | 利益相关 |

**保留的权威来源：**

| 来源类型 | 示例 | 标注方式 |
|---------|------|---------|
| 官方发布 | 发改委、证监会、交易所 | ★★★★★ |
| 监管文件 | 年报、季报、招股书 | ★★★★★ |
| 权威媒体 | WSJ、Bloomberg、Reuters、财新 | ★★★★☆ |
| 顶级机构 | 普华永道、Gartner、McKinsey报告 | ★★★★☆ |
| 交易所公告 | 上交所、深交所、港交所公告 | ★★★★★ |

---

#### 第四步：冲突检查（Conflict Verification）

**当搜到矛盾数据时：**

**处理流程：**
```
1. 识别冲突：发现两个以上来源数据不一致
2. 标注冲突：在研报中注明"While [Source A] suggests X, [Source B] points to Y"
3. 解释差异：分析来源差异原因（口径不同、时间点不同、方法论差异）
4. 标注权重：说明本研报采用哪个数据及原因
```

**冲突标注示例：**
```
市场格局：

A机构数据显示2024年市场份额35%[1]，B机构数据显示28%[2]。
差异原因：A机构采用出厂口径，B机构采用终端销售口径。
本研报采用A机构数据（as of Dec. 2025），因更接近监管披露标准。
```

### Recency Constraints (强制时间约束)

#### 禁止使用陈旧案例

**规则：**
- 严禁在研报中使用 **2年以上** 的"过时趋势"作为主要论据
- 2026年的研报禁止引用2023年及以前的市场趋势作为主要依据

**判断标准：**

| 当前年份 | 允许的最早数据年份 | 禁止使用 |
|---------|------------------|---------|
| 2026年 | 2024年 | 2023年及以前 |
| 2025年 | 2023年 | 2022年及以前 |

#### 时态对齐规则

**规则：**
- 对于2026年正在发生的事件，**必须**使用现在进行时或最近完成时
- 禁止使用过去时描述仍在持续的事件

**正确/错误示例：**

| 错误写法 | 正确写法 |
|---------|---------|
| "2024年该公司推出了新产品"（已过时） | "2025年该公司推出新一代产品，2026年持续迭代" |
| "市场预计将增长"（模糊） | "2026年市场预计增长25%（as of Q1 2026）" |
| "该公司曾是行业龙头"（已过时） | "2025年该公司市场份额35%，仍是行业龙头" |

## Part 1B: 数据来源与可信度分级（强制执行）

### 数据可信度分级标准

| 等级 | 符号 | 来源类型 | 代表性数据 | 使用建议 |
|------|------|---------|-----------|---------|
| **A级（官方）** | ★★★★★ | 政府官方文件、官方发布 | 发改委政策、国家数据局报告、国家统计年鉴 | **可直接引用** |

### 数据来源标注格式

**每个数据必须标注：**
1. 右上标来源编号：`[1]` `[2]` `[3]`
2. 参考文献中完整信息
3. 可信度分级符号

**标注示例：**

## Part 2: 研究结论推导过程规范（强制执行）

### 核心原则

**每个主要结论必须包含：**
1. **数据来源**：来自哪个文件/报告/数据库
2. **推导方法**：如何从原始数据得出该结论
3. **局限性声明**：该结论的局限性和使用建议

### 结论推导过程模板

每个重要结论后，必须附推导过程说明：

```markdown
**结论**：[核心发现]

**推导过程**：
- 数据来源：[具体来源]（可信度：★）
- 推导方法：[计算方式/分析方法]
- 局限性声明：[该结论的局限性]
```

### 推导过程示例

**示例1：市场规模类结论**

```markdown
**结论**：2024年中国数据要素市场规模达1662亿元

**推导过程**：
- 数据来源：国家数据局《全国数据资源调查报告（2024年）》[1] ★★★★★
- 推导方法：全国50+数据交易机构交易额累加 + 未入场交易估算
- 局限性声明：该数据为估算口径，与实际交易额可能存在偏差
- 验证方式：与中商产业研究院数据（2042.9亿元/2025年预测）交叉验证[6]，CAGR 20%逻辑一致

**使用建议**：可直接引用作为官方数据
```

**示例2：效率提升类结论**

```markdown
**结论**：评估效率提升12倍（评估周期从3个月压缩至1周）

**推导过程**：
- 数据来源：传统评估周期来自普华永道行业报告[4] ★★★★☆；实验室自述周期来自商业计划书[2] ★★★☆☆
- 推导方法：90天（传统）÷ 7天（实验室）= 12.86倍，取整12倍
- 计算公式：效率提升倍数 = 传统周期 ÷ 新周期 = 90 ÷ 7 ≈ 12.9 ≈ 12
- 局限性声明：实验室自述数据，未经第三方验证；传统周期为行业通行标准，实际可能因项目复杂度有所差异
- 验证建议：要求实验室提供实际项目案例第三方验证

**使用建议**：参考使用，注明"基于商业计划书自述"
```

**示例3：市场份额类结论**

```markdown
**结论**：某竞争者市场占有率约40%

**推导过程**：
- 数据来源：行业分析报告引用企业自述[3] ★★★☆☆
- 推导方法：企业自述 + 行业机构估算
- 局限性声明：市场占有率数据未经第三方机构验证，可能存在自述夸大
- 验证方式：要求提供第三方市场调研报告

**使用建议**：参考使用，建议标注"据企业自述"
```

### 推导过程检查清单

生成结论时，必须逐项确认：

- [ ] **推导-1**: 该结论的数据来源是否已标注？
- [ ] **推导-2**: 推导方法/计算方式是否已说明？
- [ ] **推导-3**: 是否标注了局限性声明？
- [ ] **推导-4**: 是否说明了验证方式（如何验证该结论）？
- [ ] **推导-5**: 是否给出了使用建议（可直接引用/参考使用/需验证）？

|--------|------|---------|

### 2. 经济逻辑驱动

**所有分析必须围绕以下核心经济要素展开：**

| 要素 | 分析维度 | 问题示例 |
|------|---------|---------|

| **监管压力** | 政策风险、合规成本 | 监管变化如何影响？ |
| **资本回报率** | ROE、ROIC、投资回收期 | 回本周期多久？IRR多少？ |

**✅ 正确示例：**

### 图表代码模板

```python

# WSJ配色
COLORS = {'primary': '#003366', 'secondary': '#D3D3D3', 'accent': '#CC0000', 'grid': '#E8E8E8'}

def plot_line_chart(data, labels, title, ylabel, filename):
    """WSJ风格折线图"""
    fig, ax = plt.subplots(figsize=(8, 4.5))
```

## Part 8: 增量进化规则（强化版）

### ⚠️ 核心原则（HIGHEST PRIORITY）

| 规则 | 说明 |
|------|------|
| **禁止重开** | 严禁在不参考旧版逻辑的情况下，直接根据新素材生成全新的、割裂的报告 |
| **禁止删除** | 旧研报中的所有内容（数据/表格/图表/段落）均不得删除 |
| **禁止覆盖** | 不得创建新文件覆盖旧文件，必须增量深化 |

---

### 规则一：继承性阅读准则 (Contextual Inheritance)

**执行动作**：在开始任何更新任务前，系统必须将"旧版研报"设为第一优先级底稿。

**逻辑对齐**：
1. 识别旧版研报中的**核心假设**
2. 判断该假设是否已在当前素材中得到**验证**
3. 如果新信息与旧假设冲突，执行"动态修正叙事"（见规则二）

**禁止重开**：严禁在不参考旧版逻辑的情况下，直接根据新素材生成全新的、割裂的报告。

---

### 规则二：内容进化逻辑 (Evolutionary Conflict Resolution)

**执行动作**：当新信息进入时，执行"保留-修正-增强"三步判断法：

#### 第一步：无冲突保留

旧版研报中没有和新信息冲突的地方，**均保留**。

```
判断逻辑：
- 新信息A vs 旧信息B
- 如果：A与B无逻辑矛盾 → 保留B，新增A
- 标记："本版本新增[A]，[B]来源于旧版"
```

#### 第二步：冲突修正 (WSJ Style Pivot)

**如果新数据与旧数据冲突，不得直接删除旧数据。**

**操作准则**：采用"动态修正叙事"。

```
错误做法：
❌ 直接删除旧数据，写入新数据
❌ "更新：旧值X → 新值Y"

正确做法（WSJ Style Pivot）：
✅ 保留旧数据，但用新数据修正叙事逻辑
```

**示例**：
```
旧版研报（2025年预测）："国产化率预计15%"

新数据（2026年实际）：实际渗透率仅3%

正确写法（WSJ Style Pivot）：
"虽然2024年预期国产化率为15%，但受限于半导体认证周期，2026年实际渗透率为3%，这表明早期预测过于乐观。"

格式要求：
- 保留旧数据和来源
- 明确指出新旧差异
- 解释差异原因
- 不删除旧预测
```

#### 第三步：深度增强

如果新素材补充了旧版缺失的技术细节，必须显著标注"进化里程碑"。

```
进化里程碑示例：
旧版（V1.0）："实验室成功验证HTS技术"
新版（V2.0）："实验室成功验证HTS技术[1]" + "★新增★工业化量产验证：2026年Q1已完成10吨/月中试量产[2]"

标注格式：
"★进化里程碑★：[从XXX进化到YYY]，时间：[ZZZ]"
```

### 13.6 主代理写入DOCX（关键步骤：主代理稳定写文件）

> ⚠️ **这是整个并行模式中最关键的步骤：主代理读取子代理的 .txt 输出，用 Python 稳定写入 DOCX**
> 禁止让子代理直接写 DOCX——子代理的 `write` 工具调用成功率 < 50%

**工作流原理：**
```
子代理：生成 markdown 文本（稳定） → 输出 .txt（稳定） → 主代理读取 → Python 写入 DOCX（稳定）
```

**子代理任务卡模板（给每个子代理的任务说明中必须包含以下关键要求）：**

```markdown
## 输出要求（必须遵守）
- ✅ 输出文件：/root/tmp/parallel_ch/ch_{X}_{Y}.txt（纯文本，不是DOCX）
- ✅ 格式：markdown 文本（包含 # 标题、## 节、表格用 |表头|形式）
- ✅ 每个子节至少300字，每个数据标注来源+可信度等级
- ❌ 禁止输出 DOCX 文件（write 工具写 DOCX 成功率极低）
- ⚠️ 子代理只负责生成 .txt 内容，文件写入由主代理执行
```

**主代理 Python 合并脚本（必须由主代理执行，禁止交给子代理）：**

```python
"""
研报合并脚本 - 主代理执行（非子代理）
读取5个子代理输出的 .txt，按顺序合并为一个完整研报DOCX
"""
from docx import Document
from docx.shared import Pt, RGBColor
from docx.enum.text import WD_ALIGN_PARAGRAPH, WD_LINE_SPACING
from docx.oxml.ns import qn
from docx.oxml import OxmlElement
import os, re

FONT_SIMHEI = 'SimHei'
FONT_SIMSUN = 'SimSun'
FONT_TIMES  = 'Times New Roman'
OUTPUT = "/root/项目研报/{项目名}研报.docx"
TEMP_DIR = "/root/tmp/parallel_ch"

def _rf(run, fname=FONT_SIMSUN, size=11, bold=False):
    run.font.name = fname; run.font.size = Pt(size); run.font.bold = bold
    x = OxmlElement('w:rFonts')
    x.set(qn('w:eastAsia'), fname)
    x.set(qn('w:ascii'), FONT_TIMES)
    x.set(qn('w:hAnsi'), FONT_TIMES)
    run._element.get_or_add_rPr().append(x)

def chap(title, size=14):
    p = doc.add_paragraph()
    p.alignment = WD_ALIGN_PARAGRAPH.CENTER
    p.paragraph_format.space_before = Pt(18)
    p.paragraph_format.space_after = Pt(10)
    p.paragraph_format.line_spacing_rule = WD_LINE_SPACING.ONE_POINT_FIVE
    r = p.add_run(title); _rf(r, FONT_SIMHEI, size, True)
    return p

def sec(title, size=12):
    p = doc.add_paragraph()
    p.paragraph_format.space_before = Pt(12)
    p.paragraph_format.space_after = Pt(4)
    p.paragraph_format.line_spacing_rule = WD_LINE_SPACING.ONE_POINT_FIVE
    r = p.add_run(title); _rf(r, FONT_SIMHEI, size, True)
    return p

def body(text, size=11):
    p = doc.add_paragraph()
    p.paragraph_format.space_before = Pt(0)
    p.paragraph_format.space_after = Pt(5)
    p.paragraph_format.line_spacing_rule = WD_LINE_SPACING.ONE_POINT_FIVE
    p.paragraph_format.first_line_indent = Pt(22)
    r = p.add_run(text); _rf(r, FONT_SIMSUN, size)
    return p

def tbl_hdr(hdrs):
    t = doc.add_table(rows=1, cols=len(hdrs)); t.style = 'Table Grid'
    for j, h in enumerate(hdrs):
        c = t.rows[0].cells[j]; c.text = ''
        p = c.add_paragraph()
        p.paragraph_format.space_before = Pt(2); p.paragraph_format.space_after = Pt(2)
        r = p.add_run(h); _rf(r, FONT_SIMSUN, 9, True)
        tcPr = c._tc.get_or_add_tcPr()
        shd = OxmlElement('w:shd')
        shd.set(qn('w:val'), 'clear'); shd.set(qn('w:color'), 'auto')
        shd.set(qn('w:fill'), '1F3864'); tcPr.append(shd)
        r.font.color.rgb = RGBColor(0xFF,0xFF,0xFF)
    doc.add_paragraph(); return t

def tbl_row(t, data):
    row = t.add_row()
    for j, v in enumerate(data):
        c = row.cells[j]; c.text = ''
        p = c.add_paragraph()
        p.paragraph_format.space_before = Pt(1); p.paragraph_format.space_after = Pt(1)
        r = p.add_run(str(v)); _rf(r, FONT_SIMSUN, 9)
    return row

def is_table_line(l):
    return l.strip().startswith('|')

def parse_content(text):
    lines = text.split('\n'); i = 0
    while i < len(lines):
        l = lines[i].strip()
        if not l: i+=1; continue
        if l.startswith('# '): chap(l[2:].strip(), 14)
        elif l.startswith('## ') or l.startswith('**第'): sec(l.lstrip('#* ').strip(), 12)
        elif l.startswith('### '): sec(l[4:].strip(), 11)
        elif is_table_line(l):
            table_lines = []
            while i < len(lines) and is_table_line(lines[i].strip()):
                table_lines.append(lines[i].strip()); i+=1
            rows = [[c.strip() for c in r.split('|')[1:-1]] for r in table_lines]
            rows = [r for r in rows if not any('---' in c for c in r)]
            if len(rows) >= 2:
                t = tbl_hdr(rows[0])
                for row in rows[1:]: tbl_row(t, row)
            continue
        elif l.startswith('- ') or l.startswith('• '): body(('• ' if l.startswith('- ') else '') + l[2:].strip())
        elif l: body(l)
        i += 1

doc = Document()
# 封面（如需要）
# chap('报告标题', 18)

CHAPTER_FILES = [
    f"{TEMP_DIR}/ch_1_2.txt",
    f"{TEMP_DIR}/ch_3_4.txt",
    f"{TEMP_DIR}/ch_5_6.txt",
    f"{TEMP_DIR}/ch_7_8.txt",
    f"{TEMP_DIR}/ch_9_10.txt",
]

for f in CHAPTER_FILES:
    if os.path.exists(f) and os.path.getsize(f) > 100:
        content = open(f, encoding='utf-8').read()
        parse_content(content)
        print(f"✓ 已合并: {os.path.basename(f)}")
    else:
        print(f"⚠ 跳过（不存在或为空）: {os.path.basename(f)}")

doc.save(OUTPUT)
print(f"\n✅ 保存完成: {OUTPUT}")
```

### 13.9 子代理文件丢失问题的根因与解决方案（重要笔记）

**问题现象：**
子代理状态显示"completed"，但对应文件未落地（大小=0或文件不存在）。常见错误信息：
```
"tool": "write"
"error": "Missing required parameter: path"
```
或文件大小正常但内容为空（被截断）。

**根因分析：**
子代理的 `write` 工具在写入 DOCX 时依赖 JSON-RPC 调用，当内容较大（>50KB）时，工具调用参数可能被截断或超时，导致文件未写入。但子代理的**文本输出通知**已先于文件写入完成，故系统仍显示"completed"。

**已验证的可靠工作流（当前唯一方案）：**
```
子代理：生成 markdown 文本（子代理擅长） → 输出 .txt（主代理检查是否落地）
主代理：读取所有 .txt → Python 解析 → 稳定写入 DOCX
```
- 子代理只负责内容生成（擅长）
- 主代理负责文件写入（稳定）
- 任何 .txt 文件缺失或过小：主代理直接用 Python 生成，不等待子代理

**历史教训：**
- ❌ 曾尝试：子代理直接写 DOCX（ch_3_4.docx 多次丢失）
- ❌ 曾尝试：子代理写 .txt 但行数<10行（不完整）
- ✅ 当前方案：子代理写 .txt + 主代理 Python 写 DOCX（100%可靠）

### 13.10 常见问题处理

| 问题 | 处理方式 |
|-----|---------|
| 某个子代理超时或文件缺失 | 主代理直接用 Python 生成对应章节，不等待 |
| 子代理生成 .txt 行数<10（不完整） | 主代理直接重新生成该章节内容 |
| 合并后格式不统一 | 主代理 Python 脚本统一修复格式 |
| 用户要求中断 | 保留已生成的 .txt 临时文件，恢复后可继续 |
| 旧研报与新章节冲突 | 保留旧数据，增量叠加新数据，标注更新时间 |
| 5个子代理中2个文件正常、3个缺失 | 主代理直接生成缺失的3个章节，然后合并（不等子代理重试）|
